## Overview

The `@Filter` decorator lets a list request narrow its results through query parameters. The default filter compares the field with six comparison operators. A custom filter function can hold any other logic.

## Basic usage

### Default filter

`@Filter()` without arguments enables the default comparison filter on a string field. Filter values stay strings. TypeScript annotations, `@Field`, and write validators do not parse them into numbers or booleans.

```typescript fragment
import { Filter } from "@antelopejs/interface-data-api/metadata";

@RegisterDataController()
class UserAPI extends DataController(
  User,
  DefaultRoutes.All,
  Controller("/users"),
) {
  @ModelReference()
  @Model(UserModel, "my-database")
  declare userModel: UserModel;

  @Listable()
  @Access(AccessMode.ReadOnly)
  declare _id: string;

  @Listable()
  @Access(AccessMode.ReadWrite)
  @Filter()
  declare status: string;

  @Listable()
  @Access(AccessMode.ReadWrite)
  @Filter()
  declare role: string;
}
```

### Query parameter format

A filter is a query parameter in one of these forms:

```
filter_<fieldName>=<value>
filter_<fieldName>=<operator>:<value>
```

Without an operator, the filter uses `eq` (equal). The text before the first colon is the operator, so a value that contains a colon needs the `eq:` prefix. The default filter answers `400` to an operator that is not in the table below.

### Comparison operators

| Operator | Description              |
| -------- | ------------------------ |
| `eq`     | Equal to (default)       |
| `ne`     | Not equal to             |
| `gt`     | Greater than             |
| `ge`     | Greater than or equal to |
| `lt`     | Less than                |
| `le`     | Less than or equal to    |

### Examples

Retrieve active users:

```http
GET /users/list?filter_status=active
```

Retrieve users whose role is not admin:

```http
GET /users/list?filter_role=ne:admin
```

Combine filters on several fields:

```http
GET /users/list?filter_status=active&filter_role=ne:admin
```

Filter one field several times to keep the rows that pass every filter (AND):

```http
GET /users/list?filter_age=ge:18&filter_age=lt:65
```

The route receives the filters of that field as a list of `FilterValue` tuples (`FieldFilter`). A field filtered once keeps a single tuple. `FilterValuesOf(filter)` from `@antelopejs/interface-data-api/metadata` reads either shape as a list. An indexed equality filter uses its index only when it is the only filter on the field.

### Numeric and boolean filters

Parse and validate numbers and booleans in a custom filter. The filters below support the six numeric comparisons and boolean `eq` and `ne`. Any other input fails with an HTTP 400 response.

```ts docs-check
import { assert } from "@antelopejs/interface-api-util";
import type { FilterFunction } from "@antelopejs/interface-data-api/metadata";

type Comparison = "eq" | "ne" | "gt" | "ge" | "lt" | "le";

const COMPARISONS: readonly Comparison[] = ["eq", "ne", "gt", "ge", "lt", "le"];

function isComparison(mode: string): mode is Comparison {
  return COMPARISONS.some((comparison) => comparison === mode);
}

export const numberFilter: FilterFunction<Record<string, unknown>> = (
  _context,
  proxy,
  _key,
  raw,
  mode,
) => {
  const text = typeof raw === "string" ? raw.trim() : "";
  const value = Number(text);
  assert(text !== "" && Number.isFinite(value), 400, "Invalid number");
  assert(isComparison(mode), 400, "Invalid comparison");
  return proxy[mode](value);
};

export const booleanFilter: FilterFunction<Record<string, unknown>> = (
  _context,
  proxy,
  _key,
  raw,
  mode,
) => {
  const value =
    raw === true || raw === "true"
      ? true
      : raw === false || raw === "false"
        ? false
        : undefined;
  assert(value !== undefined, 400, "Invalid boolean");
  assert(mode === "eq" || mode === "ne", 400, "Invalid comparison");
  return proxy[mode](value);
};
```

Apply the functions to the matching fields of your controller:

```typescript fragment
@Filter(numberFilter, false)
declare age: number;

@Filter(booleanFilter, false)
declare isActive: boolean;
```

With these custom filters, `?filter_age=gt:30&filter_isActive=true` compares against `30` and `true`, not `"30"` and `"true"`. Keep `useIndex` false for a filter that parses its value. An indexed equality lookup uses the raw value and skips the filter function.

A filter value is `string | boolean` (`FilterValue`). A request always sends text. A route may write a boolean into the filters it passes on, as an archive filter does, and every reader hands that value to the database unchanged: the field's filter, the default filter and the indexed lookup.

## Custom filters

For logic beyond the comparison operators, pass a custom filter function to `@Filter`.

### Filter function signature

```typescript fragment
type FilterFunction<
  T extends Record<string, any>,
  U extends Record<string, any> = FieldValues,
> = (
  context: RequestContext & { this: T },
  proxy: ValueProxy<any>,
  key: string,
  ...rest: [value: FilterValue[0], mode: FilterValue[1], row: ValueProxy<U>]
) => ValueProxyOrValue<boolean>;
```

| Parameter | Description                                                                                              |
| --------- | -------------------------------------------------------------------------------------------------------- |
| `context` | The request context, with `this` set to the controller instance                                          |
| `proxy`   | A query expression that the field modifier's `unlockrequest()` method builds. See the limitations below. |
| `key`     | The name of the filtered field                                                                           |
| `value`   | The filter value from the query parameter, a string                                                      |
| `mode`    | The text before the first colon of the query parameter, unchecked. The filter defines its own modes.     |
| `row`     | The full database row as a `ValueProxy`                                                                  |

`value`, `mode`, and `row` form one rest tuple, so the function type stays within five parameters. A function that declares them as separate parameters is assignable to the type, and `Parameters<FilterFunction<T, U>>` lists all six.

### Example: pattern matching filter

```typescript fragment
function filterByEmailDomain(
  context: RequestContext,
  proxy: ValueProxy<any>,
  key: string,
  value: string,
  mode: string,
  row: ValueProxy<Record<string, any>>,
) {
  assert(mode === "eq", 400, "Only equality is supported for email domains");
  const escaped = value.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
  return proxy.match(`@${escaped}$`);
}

@RegisterDataController()
class UserAPI extends DataController(
  User,
  DefaultRoutes.All,
  Controller("/users"),
) {
  @ModelReference()
  @Model(UserModel, "my-database")
  declare userModel: UserModel;

  @Listable()
  @Access(AccessMode.ReadWrite)
  @Filter(filterByEmailDomain)
  declare email: string;

  @Listable()
  @Access(AccessMode.ReadWrite)
  @Filter(numberFilter, false)
  declare age: number;
}
```

Query for users with Gmail addresses:

```http
GET /users/list?filter_email=gmail.com
```

Import `assert` from `@antelopejs/interface-api-util`. The function escapes the domain, so the dot matches a literal dot and not any character. The function rejects operators other than `eq`, so a request with another operator fails instead of running as an equality filter.

### The `useIndex` parameter

The second parameter of `@Filter`, `useIndex`, allows the filter to use a database index.

```typescript fragment
@Filter(undefined, true)   // Default filter with index optimization
declare status: string;

@Filter(customFilter, false) // Custom filter without index optimization
declare name: string;
```

When `useIndex` is not set:

- The default filter (no custom function) uses the index when the field has a single-field index.
- A custom filter uses no index.

An indexed filter with the `eq` operator reads the matching rows through the index instead of scanning the whole table.

## Mandatory route filters

`DefaultRoutes.WithOptions` can constrain a list route. Its `filters` map holds `[stringValue, comparison]` tuples for fields declared with `@Filter`. The route keeps request filters on other fields. When the route and the request filter the same field, the route filter wins.

```ts docs-check
import { DefaultRoutes } from "@antelopejs/interface-data-api";

const activeUsers = DefaultRoutes.WithOptions(DefaultRoutes.List, {
  filters: { status: ["active", "eq"] },
});
```

On a controller with a `status` filter, `?filter_status=inactive&filter_role=admin` still restricts `status` to `"active"` and keeps the requested `role`. Route filters constrain list queries only. They do not authorize or restrict the `get`, `edit`, or `delete` routes.

## Modifier integration

The `proxy` parameter is a database expression, not an unlocked model instance. The Data API calls the modifier's `unlockrequest()` method to build that expression. Localization can select a locale at query time. The built-in `EncryptionModifier.unlockrequest()` returns the stored expression unchanged, so it does not decrypt ciphertext in the database. A custom modifier must support query-time access before a filter can compare its plain value.

For raw database values, read the field from the `row` parameter.
