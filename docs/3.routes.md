## Overview

Routes define which operations a data controller serves. The `DefaultRoutes` namespace holds ready-made routes. Each one sets its HTTP method, the parameters it reads from the request and the response it sends.

## Default routes

The `DefaultRoutes` namespace holds five routes for the CRUD operations.

```typescript
import { DefaultRoutes } from "@antelopejs/interface-data-api";
```

| Route  | Object                 | HTTP method | Endpoint pattern           |
| ------ | ---------------------- | ----------- | -------------------------- |
| Get    | `DefaultRoutes.Get`    | GET         | `/resource/get?id=<id>`    |
| List   | `DefaultRoutes.List`   | GET         | `/resource/list`           |
| New    | `DefaultRoutes.New`    | POST        | `/resource/new`            |
| Edit   | `DefaultRoutes.Edit`   | PUT         | `/resource/edit?id=<id>`   |
| Delete | `DefaultRoutes.Delete` | DELETE      | `/resource/delete?id=<id>` |

`DefaultRoutes.All` holds all five routes under the keys `get`, `list`, `new`, `edit` and `delete`.

## Route configuration

The route definition object you pass to `DataController` decides which endpoints exist. Each key is an endpoint name.

```typescript fragment
// All CRUD routes
@RegisterDataController()
class UserAPI extends DataController(
  User,
  DefaultRoutes.All,
  Controller("/users"),
) {
  // ...
}

// Only specific routes
@RegisterDataController()
class UserAPI extends DataController(
  User,
  {
    get: DefaultRoutes.Get,
    list: DefaultRoutes.List,
    new: DefaultRoutes.New,
  },
  Controller("/users"),
) {
  // no edit or delete endpoint
}
```

## Route details

### Get

Reads one record by its identifier. The endpoint is `GET /resource/get`.

| Query parameter | Required | Description       |
| --------------- | -------- | ----------------- |
| `id`            | Yes      | Record identifier |

A request without `id` answers `400` with `Missing id.`. A missing record answers `404 Not Found`.

```http
GET /users/get?id=user-123
```

The response holds the readable fields of the record.

```json
{
  "_id": "user-123",
  "name": "Bob",
  "email": "bob@example.com"
}
```

### List

Reads one page of records, with sorting and filtering. The endpoint is `GET /resource/list`.

| Query parameter  | Required | Default              | Description                                                                                      |
| ---------------- | -------- | -------------------- | ------------------------------------------------------------------------------------------------ |
| `limit`          | No       | `maxPage`, else `10` | Maximum number of records to return. The route caps it at `maxPage`, or at `100` without one.    |
| `offset`         | No       | `0`                  | Number of records to skip                                                                        |
| `sortKey`        | No       | none                 | Field to sort by. The field needs `@Sortable`, or the route answers `400 Field is not sortable.` |
| `sortDirection`  | No       | `asc`                | `asc` or `desc`. Any other value sorts ascending.                                                |
| `filter_<field>` | No       | none                 | A filter on a field declared with `@Filter`. See [filters](./8.filters.md).                      |

```http
GET /users/list?limit=10&offset=0&sortKey=name&sortDirection=asc
```

The response holds the page, the total count of matching records, and the `offset` and `limit` the route used.

```json
{
  "results": [
    { "_id": "user-123", "name": "Alice", "email": "alice@example.com" },
    { "_id": "user-456", "name": "Bob", "email": "bob@example.com" }
  ],
  "total": 42,
  "offset": 0,
  "limit": 10
}
```

### New

Creates a record. The endpoint is `POST /resource/new`, and the body is a JSON object with the field values.

```http
POST /users/new
Content-Type: application/json

{
  "name": "Bob",
  "email": "bob@example.com",
  "password": "secure123"
}
```

The response is the created record, as [Get](#get) answers it, with its `_id` even when `get` does not read `_id`.

```json
{
  "_id": "user-789",
  "name": "Bob",
  "email": "bob@example.com"
}
```

The row starts from the defaults the controller class declares. Every writable field is then written. A field absent from the body is written as `undefined`, and every writable setter of the controller runs, with `undefined` for an absent field. The route answers `400 Bad Request` for a body that is not valid JSON or not a JSON object.

Before the insert, the route triggers the `insert` event on the modifiers of the table.

### Edit

Updates a record by its identifier. The endpoint is `PUT /resource/edit`.

| Query parameter | Required | Description       |
| --------------- | -------- | ----------------- |
| `id`            | Yes      | Record identifier |

The body is a JSON object with the fields to update. The route writes only the fields present in the body.

| In the body | Effect on the field |
| ----------- | ------------------- |
| key absent  | unchanged           |
| `null`      | cleared             |
| a value     | set                 |

Writable setters run only for the fields present in the body. A modifier field (localized or encrypted, for example) absent from the body keeps its stored value in every language.

A request without `id` answers `400` with `Missing id.`. A missing record answers `404 Not Found`. A body that is not valid JSON or not a JSON object answers `400 Bad Request`.

```http
PUT /users/edit?id=user-123
Content-Type: application/json

{
  "name": "Robert",
  "email": "robert@example.com"
}
```

The response is the stored record after the update, as [Get](#get) answers it, with joined, computed and foreign fields. The caller needs no second read.

```json
{
  "_id": "user-123",
  "name": "Robert",
  "email": "robert@example.com"
}
```

Before the update, the route triggers the `update` event on the modifiers of the table.

### Delete

Deletes one or more records by their identifiers. The endpoint is `DELETE /resource/delete`.

| Query parameter | Required | Description                                                                         |
| --------------- | -------- | ----------------------------------------------------------------------------------- |
| `id`            | Yes      | Record identifier. Repeat the `id` parameter to delete several records in one call. |

A request without `id` answers `400` with `Missing id.`.

```http
DELETE /users/delete?id=user-123
```

The route answers `200 OK`. The body is the number of records the database deleted. An identifier that matches no record is not an error.

```http
200 OK
```

## Route options with `WithOptions`

`DefaultRoutes.WithOptions` customizes a route. It sets route options, which take precedence over the query parameters of the same name, and it can rename the endpoint.

```typescript fragment
DefaultRoutes.WithOptions(callback, options?, endpoint?)
```

| Parameter  | Description                                                                                                                      |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `callback` | The route to customize, such as `DefaultRoutes.Edit`, or a route `WithOptions` already returned. In that case the options merge. |
| `options`  | An object of option values. A query parameter with the same name is ignored. Route `filters` combine with the request's filters. |
| `endpoint` | A custom endpoint path. It defaults to the route key in the definition object.                                                   |

### Example

```typescript fragment
const routes = {
  edit: DefaultRoutes.Edit,
  quickEdit: DefaultRoutes.WithOptions(DefaultRoutes.Edit, {
    noMandatory: "true",
  }),
};

@RegisterDataController()
class UserAPI extends DataController(User, routes, Controller("/users")) {
  // /users/edit checks mandatory fields
  // /users/quickEdit skips the mandatory field check
}
```

### Available options per route

The string options `noForeign` and `noMandatory` take effect for any non-empty string, `"false"` included.

The Get route takes these options.

| Option      | Type     | Description                                                          |
| ----------- | -------- | -------------------------------------------------------------------- |
| `index`     | `string` | Read the record through a secondary index instead of the primary key |
| `noForeign` | `string` | Skip foreign key resolution                                          |

The List route takes these options.

| Option      | Type                          | Description                                                                                                                  |
| ----------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `maxPage`   | `number`                      | Maximum value of `limit`, and the page size when the request sends no `limit`. Without it, the cap is `100`.                 |
| `noForeign` | `boolean`                     | Skip foreign key resolution                                                                                                  |
| `noPluck`   | `boolean`                     | Skip the database pluck. The response still holds only the fields readable in `list`                                         |
| `pluckMode` | `string`                      | Select a named pluck mode (see `@Listable`). A mode that no field declares answers `400`.                                    |
| `filters`   | `Record<string, FieldFilter>` | Mandatory filters merged with request filters. Route field keys win (see [filters](./8.filters.md#mandatory-route-filters)). |

The New route takes this option.

| Option        | Type     | Description                    |
| ------------- | -------- | ------------------------------ |
| `noMandatory` | `string` | Skip the mandatory field check |

The Edit route takes these options.

| Option        | Type     | Description                                                                                                                |
| ------------- | -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `index`       | `string` | Find the record through a secondary index instead of the primary key. The update and the response target the record found. |
| `noMandatory` | `string` | Skip the mandatory field check                                                                                             |

## Amending the body of `new` and `edit`

The `new` and `edit` routes take the raw request body (`Buffer`) or a body already parsed (`Validation.WrittenBody`). A route that wraps them can parse the body, amend it (stamp a field or drop one) and pass the object on. The route validates and writes the object as it receives it, with no second serialization.

A parsed body is `FieldValues`, which holds fields by name. Each field holds a `FieldValue`: a string, a number, a boolean, `null`, a `Date`, or an array or plain object of those. `Validation.ParseBody` answers `400` for anything else, whether it comes from a `Buffer` or from a body already parsed. That includes a function, a class instance, a `bigint`, a cycle and an `undefined` array element.

The default routes run with the controller as `this`. A wrapping function declares `this: DataControllerInstance` and calls `route.func.call(this, ...)`.

```ts docs-check
import {
  DefaultRoutes,
  type DataControllerInstance,
} from "@antelopejs/interface-data-api";
import {
  type Parameters,
  Validation,
} from "@antelopejs/interface-data-api/components";
import type { RequestContext } from "@antelopejs/interface-api";

const stampedNew = {
  ...DefaultRoutes.New,
  func: function (
    this: DataControllerInstance,
    ctx: RequestContext,
    params: Parameters.NewParameters,
    body: Buffer,
  ) {
    const parsed = Validation.ParseBody(body);
    parsed.source = "import";
    return DefaultRoutes.New.func.call(this, ctx, params, parsed);
  },
};
```

## Loaded-model guards with `WithGetGuard`

`DefaultRoutes.WithGetGuard(guard)` returns a Get route that awaits a guard after it loads and unlocks the model. The guard runs before the route selects the readable fields and applies the response getters. A guard can check a stored discriminator or ownership field that never appears in the response.

```ts docs-check
import { DefaultRoutes } from "@antelopejs/interface-data-api";
import { assert } from "@antelopejs/interface-api-util";

const invoiceGet = DefaultRoutes.WithGetGuard(
  async function (ctx, current, params) {
    // The table stores documentType, and no @Access exposes it.
    assert(current.documentType === "invoice", 404, "Not Found");
  },
);

// Pass this route map to DataController(Document, routes, Controller("/invoices")).
const routes = {
  get: DefaultRoutes.WithOptions(invoiceGet, { noForeign: "true" }),
};
```

The `GetGuard` callback receives `(ctx, current, params)`. Declare it as a regular function to reach the controller through `this`, typed `DataControllerInstance`. That type is `object`, with no string index, so narrow `this` (with `instanceof` your controller class, for example) before you read a controller field. `current` is a `StoredRow`: each value is one a database stores (`WriteValue`), a relation's row instance, a nested `StoredRow` or a list of those.

| Argument  | Contents                                                                                          | Use it for                                  |
| --------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `ctx`     | Request context                                                                                   | Policy that depends on the request          |
| `current` | Loaded model, with the fields no `@Access` reads and the joined, computed and foreign data of Get | Checking stored ownership or discriminators |
| `params`  | `Parameters.GetParameters`                                                                        | The parsed Get parameters                   |

Treat `current` as read-only. It is not the response object, and the API does not freeze it.

A guard follows these rules.

- **Deny by throwing.** Throw an `HTTPResult` or call `assert`. A normal return allows the read, even a return value of `false`.
- **A missing record skips the guard.** The route answers `404` without calling it.
- **The guard reads the loaded model.** It issues no second read and does not change field access rules.
- **Each route needs its own guard.** The guard applies only to the route that uses it, not to the list, edit or delete routes.

## Custom routes

For operations beyond CRUD, define a route callback with `func`, `args` and `method` properties.

```typescript fragment
import { Context } from "@antelopejs/interface-api";
import {
  DataController,
  DefaultRoutes,
  RegisterDataController,
} from "@antelopejs/interface-data-api";
import { Parameters } from "@antelopejs/interface-data-api/components";

const Search = {
  func: async (ctx, params) => {
    // Custom search logic
    return { results: [] };
  },
  args: [Context(), Parameters.List()],
  method: "get",
};

@RegisterDataController()
class UserAPI extends DataController(
  User,
  {
    ...DefaultRoutes.All,
    search: Search,
  },
  Controller("/users"),
) {
  // All default routes plus a custom /users/search endpoint
}
```

The `args` array holds parameter decorators that read values from the request context. Entry `i` of `args` supplies parameter `i` of `func`.

`DataControllerCallback<O, R, A>` states that pairing. `A` is the tuple of what `func` receives, and `args` holds one decorator per element of `A`. The default routes declare their tuple. `DefaultRoutes.Get` takes `[RequestContext, Parameters.GetParameters]`, and `DefaultRoutes.New` and `DefaultRoutes.Edit` add the `Validation.WrittenBody`. A route that wraps one of them can be generic over the tuple and call `route.func.call(this, ...)` with typed arguments. Without `A`, the parameters are unknown and unchecked. A `DataControllerDef` holds routes of that type.

```ts docs-check
import type { RequestContext } from "@antelopejs/interface-api";
import {
  type DataControllerCallback,
  type DataControllerInstance,
  DefaultRoutes,
} from "@antelopejs/interface-data-api";
import type { Parameters } from "@antelopejs/interface-data-api/components";

function withLoggedId<O, R, Rest extends unknown[]>(
  route: DataControllerCallback<
    O,
    R,
    [RequestContext, Parameters.GetParameters, ...Rest]
  >,
): DataControllerCallback<
  O,
  R,
  [RequestContext, Parameters.GetParameters, ...Rest]
> {
  return {
    ...route,
    func: function (this: DataControllerInstance, ctx, params, ...rest) {
      console.log(params.id);
      return route.func.call(this, ctx, params, ...rest);
    },
  };
}

const loggedGet = withLoggedId(DefaultRoutes.Get);
```

## Error handling

The default routes answer with these HTTP errors.

| Status                      | Condition                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `400 Bad Request`           | A field fails its validator, a mandatory field is missing, the body is not a JSON object, or a parameter is missing or invalid |
| `404 Not Found`             | The record does not exist                                                                                                      |
| `500 Internal Server Error` | The database operation fails, the controller holds no model, or a row holds a value no database stores (see below)             |

A row holds only values a database stores: text, numbers, booleans, `null`, `undefined`, dates, and arrays or objects of those. A route answers `500` when a getter it reads returns a `bigint`, a `symbol` or a function, when the default the controller class declares for a decorated field is one, when a setter writes one into the row, or when a related row holds one. Convert the value in the getter, default or setter, for example `String(total)` for a `bigint`, or keep a callback out of the decorated fields.

A failed mandatory or validator check answers a JSON body with a `code` and the `fields` concerned (see [validators](./5.validators.md#error-handling)). Every other error the routes raise answers its message as text, such as `Missing id.` or `Not Found`.
