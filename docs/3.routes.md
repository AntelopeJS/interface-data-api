# Routes

## Overview

Routes define which operations are available on a data controller. The module provides predefined route configurations that automatically generate endpoints with the correct HTTP methods, parameter extraction, and response handling.

## Default Routes

The `DefaultRoutes` namespace provides five built-in routes covering standard CRUD operations.

```typescript
import { DefaultRoutes } from "@antelopejs/interface-data-api";
```

| Route  | Object                 | HTTP Method | Endpoint Pattern           |
| ------ | ---------------------- | ----------- | -------------------------- |
| Get    | `DefaultRoutes.Get`    | GET         | `/resource/get?id=<id>`    |
| List   | `DefaultRoutes.List`   | GET         | `/resource/list`           |
| New    | `DefaultRoutes.New`    | POST        | `/resource/new`            |
| Edit   | `DefaultRoutes.Edit`   | PUT         | `/resource/edit?id=<id>`   |
| Delete | `DefaultRoutes.Delete` | DELETE      | `/resource/delete?id=<id>` |

Use `DefaultRoutes.All` to include all five routes at once.

## Route Configuration

Pass a route definition object to `DataController` to control which endpoints are created.

```typescript fragment
// All CRUD routes
@RegisterDataController()
class UserAPI extends DataController(
  User,
  DefaultRoutes.All,
  Controller("/users"),
) {
  // ...
}

// Only specific routes
@RegisterDataController()
class UserAPI extends DataController(
  User,
  {
    get: DefaultRoutes.Get,
    list: DefaultRoutes.List,
    new: DefaultRoutes.New,
  },
  Controller("/users"),
) {
  // edit and delete endpoints are not created
}
```

## Route Details

### Get

Retrieves a single record by its identifier.

**Endpoint:** `GET /resource/get`

**Query Parameters:**

| Parameter | Required | Description       |
| --------- | -------- | ----------------- |
| `id`      | Yes      | Record identifier |

**Example:**

```http
GET /users/get?id=user-123
```

**Response:**

```json
{
  "_id": "user-123",
  "name": "Bob",
  "email": "bob@example.com"
}
```

### List

Retrieves multiple records with pagination, sorting, and filtering support.

**Endpoint:** `GET /resource/list`

**Query Parameters:**

| Parameter       | Required | Default | Description                                   |
| --------------- | -------- | ------- | --------------------------------------------- |
| `limit`         | No       | `10`    | Maximum number of records to return           |
| `offset`        | No       | `0`     | Number of records to skip                     |
| `sortKey`       | No       | -       | Field to sort by (must be marked `@Sortable`) |
| `sortDirection` | No       | `asc`   | Sort direction: `asc` or `desc`               |

**Example:**

```http
GET /users/list?limit=10&offset=0&sortKey=name&sortDirection=asc
```

**Response:**

```json
{
  "results": [
    { "_id": "user-123", "name": "Alice", "email": "alice@example.com" },
    { "_id": "user-456", "name": "Bob", "email": "bob@example.com" }
  ],
  "total": 42,
  "offset": 0,
  "limit": 10
}
```

### New

Creates a new record. The request body must be a JSON object with the fields to set.

**Endpoint:** `POST /resource/new`

**Body:** JSON object with field values.

**Example:**

```http
POST /users/new
Content-Type: application/json

{
  "name": "Bob",
  "email": "bob@example.com",
  "password": "secure123"
}
```

**Response:** the created record, as [Get](#get) answers it, with its `_id` even when `get` does not read it.

```json
{
  "_id": "user-789",
  "name": "Bob",
  "email": "bob@example.com"
}
```

Every writable field is written: a field absent from the body is written as `undefined`, and every writable setter of the controller runs (with `undefined` for absent fields). A body that is not valid JSON or not a JSON object is rejected with `400 Bad Request`.

Before inserting, the `insert` event is triggered on any table modifiers attached to the database table.

### Edit

Updates an existing record by its identifier.

**Endpoint:** `PUT /resource/edit`

**Query Parameters:**

| Parameter | Required | Description       |
| --------- | -------- | ----------------- |
| `id`      | Yes      | Record identifier |

**Body:** JSON object with the fields to update. Only the fields present in the body are written:

| In the body | Effect on the field |
| ----------- | ------------------- |
| key absent  | unchanged           |
| `null`      | cleared             |
| a value     | set                 |

Writable setters only run for the fields present in the body. Modifier fields (localized, encrypted…) absent from the body keep their stored value in every language.

A missing record answers `404 Not Found`. A body that is not valid JSON or not a JSON object is rejected with `400 Bad Request`.

**Example:**

```http
PUT /users/edit?id=user-123
Content-Type: application/json

{
  "name": "Robert",
  "email": "robert@example.com"
}
```

**Response:** the stored record after the update, as [Get](#get) answers it (joined, computed and foreign fields included), so the caller needs no second read.

```json
{
  "_id": "user-123",
  "name": "Robert",
  "email": "robert@example.com"
}
```

Before updating, the `update` event is triggered on any table modifiers attached to the database table.

### Delete

Deletes one or more records by their identifiers.

**Endpoint:** `DELETE /resource/delete`

**Query Parameters:**

| Parameter | Required | Description                                                                            |
| --------- | -------- | -------------------------------------------------------------------------------------- |
| `id`      | Yes      | Record identifier(s). Pass multiple `id` parameters to delete several records at once. |

**Example:**

```http
DELETE /users/delete?id=user-123
```

**Response:**

```http
200 OK
```

## Route Options with `WithOptions`

The `DefaultRoutes.WithOptions` function customizes route behavior by overriding query parameters or route settings.

```typescript fragment
DefaultRoutes.WithOptions(callback, options?, endpoint?)
```

| Parameter  | Description                                                                          |
| ---------- | ------------------------------------------------------------------------------------ |
| `callback` | The route callback to customize (e.g., `DefaultRoutes.Edit`).                        |
| `options`  | An object with option overrides. These values take precedence over query parameters. |
| `endpoint` | An optional custom endpoint path. Defaults to the route key name.                    |

### Example

```typescript fragment
const routes = {
  edit: DefaultRoutes.Edit,
  quickEdit: DefaultRoutes.WithOptions(DefaultRoutes.Edit, {
    noMandatory: "true",
  }),
};

@RegisterDataController()
class UserAPI extends DataController(User, routes, Controller("/users")) {
  // /users/edit enforces mandatory fields
  // /users/quickEdit skips mandatory field validation
}
```

### Available Options per Route

**Get:**

| Option      | Type     | Description                                      |
| ----------- | -------- | ------------------------------------------------ |
| `index`     | `string` | Use a secondary index instead of the primary key |
| `noForeign` | `string` | Skip foreign key resolution                      |

**List:**

| Option      | Type                          | Description                                                                                                                  |
| ----------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `maxPage`   | `number`                      | Maximum allowed value for `limit` (caps the page size)                                                                       |
| `noForeign` | `boolean`                     | Skip foreign key resolution                                                                                                  |
| `noPluck`   | `boolean`                     | Return all database fields instead of plucked fields                                                                         |
| `pluckMode` | `string`                      | Select a named pluck mode (see `@Listable`)                                                                                  |
| `filters`   | `Record<string, FieldFilter>` | Mandatory filters merged with request filters; route field keys win (see [filters](./8.filters.md#mandatory-route-filters)). |

**New:**

| Option        | Type     | Description                     |
| ------------- | -------- | ------------------------------- |
| `noMandatory` | `string` | Skip mandatory field validation |

**Edit:**

| Option        | Type     | Description                                      |
| ------------- | -------- | ------------------------------------------------ |
| `index`       | `string` | Use a secondary index instead of the primary key |
| `noMandatory` | `string` | Skip mandatory field validation                  |

## Amending the Body of New and Edit

The `new` and `edit` routes take the raw request body (`Buffer`) or a body already parsed (`Validation.WrittenBody`). A route wrapping them can parse the body, amend it (stamp a field, drop one) and hand the object on: the route validates and writes it as handed, without a second serialization.

A parsed body is `FieldValues`: fields by name, each holding a `FieldValue` (a string, number, boolean, `null`, `Date`, or an array or plain object of those). `Validation.ParseBody` answers 400 for anything else, whether it comes from a `Buffer` or from a body already parsed: a function, a class instance, a `bigint`, a cycle or an `undefined` array element. The default routes run with the controller as `this`, so a wrapping function declares `this: DataControllerInstance` and calls `route.func.call(this, ...)`.

```ts docs-check
import {
  DefaultRoutes,
  type DataControllerInstance,
} from "@antelopejs/interface-data-api";
import {
  type Parameters,
  Validation,
} from "@antelopejs/interface-data-api/components";
import type { RequestContext } from "@antelopejs/interface-api";

const stampedNew = {
  ...DefaultRoutes.New,
  func: function (
    this: DataControllerInstance,
    ctx: RequestContext,
    params: Parameters.NewParameters,
    body: Buffer,
  ) {
    const parsed = Validation.ParseBody(body);
    parsed.source = "import";
    return DefaultRoutes.New.func.call(this, ctx, params, parsed);
  },
};
```

## Loaded-Model Guards with `WithGetGuard`

`DefaultRoutes.WithGetGuard(guard)` returns a Get route that awaits a guard after loading and unlocking the model, but before selecting readable fields and applying response getters. Use it to check a stored discriminator or ownership field that must not appear in the response.

```ts docs-check
import { DefaultRoutes } from "@antelopejs/interface-data-api";
import { assert } from "@antelopejs/interface-api-util";

const invoiceGet = DefaultRoutes.WithGetGuard(
  async function (ctx, current, params) {
    // documentType can be stored without being exposed through @Access.
    assert(current.documentType === "invoice", 404, "Not Found");
  },
);

// Pass this route map to DataController(Document, routes, Controller("/invoices")).
const routes = {
  get: DefaultRoutes.WithOptions(invoiceGet, { noForeign: "true" }),
};
```

The `GetGuard` callback receives `(ctx, current, params)`. Declare it as a regular function to access the controller through `this`, typed `DataControllerInstance`. `current` is `FieldValues`.

| Argument  | Contents                                                                                | Use it for                                     |
| --------- | --------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `ctx`     | Request context                                                                         | Request-specific policy.                       |
| `current` | Loaded model, including non-readable fields and normal Get joined/computed/foreign data | Inspecting stored ownership or discriminators. |
| `params`  | `Parameters.GetParameters`                                                              | The parsed Get parameters.                     |

Treat `current` as read-only: it is not the response DTO and the API does not freeze it.

Keep these boundaries when writing a guard:

- **Deny by throwing.** Throw an `HTTPResult` or use `assert`. A normal return permits the read, including a return value of `false`.
- **Missing records bypass the guard.** The route returns `404` without invoking it.
- **Use the already-loaded model.** The guard does not issue a second read or change field-access rules.
- **Protect each route deliberately.** The guard applies only to the route using it, not list, edit, or delete routes.

## Custom Routes

For operations beyond CRUD, define a custom route callback with `func`, `args`, and `method` properties.

```typescript fragment
import { Context } from "@antelopejs/interface-api";
import {
  DataController,
  DefaultRoutes,
  RegisterDataController,
} from "@antelopejs/interface-data-api";
import { Parameters } from "@antelopejs/interface-data-api/components";

const Search = {
  func: async (ctx, params) => {
    // Custom search logic
    return { results: [] };
  },
  args: [Context(), Parameters.List()],
  method: "get",
};

@RegisterDataController()
class UserAPI extends DataController(
  User,
  {
    ...DefaultRoutes.All,
    search: Search,
  },
  Controller("/users"),
) {
  // All default routes plus a custom /users/search endpoint
}
```

The `args` array contains parameter decorators that extract values from the request context. Each decorator corresponds to a parameter in the `func` callback, in order.

`DataControllerCallback<O, R, A>` states that pairing: `A` is the tuple of what `func` receives, and `args` holds one decorator per element of `A`. The default routes declare theirs (`DefaultRoutes.Get` takes `[RequestContext, Parameters.GetParameters]`, `DefaultRoutes.New` and `Edit` add the `Validation.WrittenBody`), so a route wrapping one can be generic over the tuple and call `route.func.call(this, ...)` with typed arguments. Without `A`, the parameters are not known and not checked: that is the type a `DataControllerDef` holds.

```ts docs-check
import type { RequestContext } from "@antelopejs/interface-api";
import {
  type DataControllerCallback,
  type DataControllerInstance,
  DefaultRoutes,
} from "@antelopejs/interface-data-api";
import type { Parameters } from "@antelopejs/interface-data-api/components";

function withLoggedId<O, R, Rest extends unknown[]>(
  route: DataControllerCallback<
    O,
    R,
    [RequestContext, Parameters.GetParameters, ...Rest]
  >,
): DataControllerCallback<
  O,
  R,
  [RequestContext, Parameters.GetParameters, ...Rest]
> {
  return {
    ...route,
    func: function (this: DataControllerInstance, ctx, params, ...rest) {
      console.log(params.id);
      return route.func.call(this, ctx, params, ...rest);
    },
  };
}

const loggedGet = withLoggedId(DefaultRoutes.Get);
```

## Error Handling

Default routes return standard HTTP error responses:

| Status                      | Condition                                                        |
| --------------------------- | ---------------------------------------------------------------- |
| `400 Bad Request`           | Validation fails, missing required fields, or invalid parameters |
| `404 Not Found`             | Record does not exist                                            |
| `500 Internal Server Error` | Database operation fails                                         |

Error messages are returned as plain text in the response body.
